# 사용자가 작성한 일정의 일별 AI 수정 검증

2026-10-31 (Asia/Seoul), `work` 브랜치. 대상은 직접 작성한 엑셀을 지도에 표시한 뒤 선택한 하루만 수정하는 흐름이다. 실제 사용자 프로필·여행은 사용하지 않았으며, 별도 Chromium과 비영속 컨텍스트에서 테스트용 후쿠오카 여행을 사용했다.

## 구현

- `276925a`: AI 응답을 요청하는 공통 코드, 날짜별 입력 추출, 응답 검증·병합과 단위 검사(P1).
- `68a505e`: 일별 수정 버튼, 잠금, 비교 화면, 새 장소 확인, 적용·저장·되돌리기 및 브라우저 검사(P2).
- 선택한 하루의 모든 행(장소 없는 이동 행 포함)을 문맥으로 사용한다. 빈 날짜는 위 날짜를 상속한다. 날짜 열이 없으면 분류 열을 사용한다.
- 기존 행은 원래 메모·추가 열을 유지하고, AI 참고 사항을 별도로 덧붙인다. 다른 날짜·보관함은 보존한다. 기존 장소 교체는 제거+새 장소로 표현해 변경이 드러나게 한다.
- 장소·시간을 잠근 행을 삭제하거나 시간을 변경한 응답, 다른 날짜의 행 참조, 중복 ID, 잘못된 시간은 거부한다. 삭제될 행과 그 메모를 적용 전에 보여 준다.
- 새 장소는 Google 검증에서 위치를 찾지 못하거나 휴관·이름 불일치 등이 있으면 적용을 막는다. 기존 장소의 영업시간을 모두 다시 검증하는 기능은 아니다.
- 원본이 변경됐거나 저장 실패·탭 간 충돌이 발생하면 수정안을 반영하지 않는다. AI 요청 취소/창 닫기 이후의 늦은 응답은 무시한다. 적용 후 새 경로는 사용자가 ‘경로 찾기’로 요청한다.

## 실제 API 검증

[실행 결과](evidence/day-revision/live/results.json) · [수정안 화면](evidence/day-revision/live/preview.png) · [재열기 화면](evidence/day-revision/live/reopened.png)

실제 Google 지도와 Gemini를 사용했고 응답 대역은 사용하지 않았다. 위도·경도를 포함한 사용자 엑셀의 2일·3행을 업로드하고 지도 표시 → 11월 7일 선택 → 오전 공원 잠금 → ‘미술관을 13:00–14:00으로 늦추고 기존 두 장소만 유지’ 요청 → 수정안 확인 → 적용 → 새로고침 → 이어서 준비하기를 실행했다.

**통과:** Gemini HTTP 200, 적용 전 원본 유지, 미술관 `11:30–12:30 → 13:00–14:00`, 잠근 오전 일정·개인 메모·추가 열·11월 8일 일정 보존, 재열기 후 시간 유지, 실제 지도 렌더링. API 응답에 기록된 총 토큰은 889개이며 금액을 환산하지 않았다. 이 실제 실행은 기존 장소의 시간 수정이며 **새 장소 추가는 아래 모의 검사에서 검증했다.** Claude/OpenAI의 실제 API를 이번에 호출하지 않았다.

첫 실제 시도에서는 사진용 Google 장소 이름·ID 자동 보충을 사용자 편집으로 오인해 요청 시작을 막았다. [실패 기록](evidence/day-revision/live/before-fingerprint-fix.json)을 보존했다. 비교 기준을 사용자 데이터·핀 좌표 중심으로 바꾸고, 적용 시 최신 장소 메타데이터를 사용하도록 수정했다. 핀 이동·메모 편집은 여전히 충돌로 감지한다. 수정 후 위 실제 실행이 통과했다.

## 재현

환경은 Node 24.19.0, Chromium 154.0.8037.57, Playwright 1.62.1이다. 실행 중인 로컬 서버가 필요하다.

```bash
PORT=8093 node server.js --no-open
# 별도 터미널
npm test
node tests/browser/day-revision.cjs
APP_URL=http://127.0.0.1:8093 NEGATIVE_OUT=/tmp/day-revision-negative node docs/testing/repro/negative-78.cjs
```

실제 검사는 `node tests/browser/day-revision-live.cjs`로 별도 실행한다. 환경의 Google·Gemini 키, 테스트 리퍼러 허용, 관리형 프록시와 Chromium의 환경 CA 신뢰가 필요하며 실제 API 사용량이 발생한다. TLS 검증을 끄지 않는다. 키·브라우저 저장소 덤프·요청 헤더를 증거에 보관하지 않는다. Google Fonts와 환율 도메인의 허용 정책은 이번 기능 변경 범위에 포함하지 않았다.
