# RouteFlow 상용 배포 전 종합 점검표 및 코드 리뷰

> 아래는 수정 전 코드 리뷰 기록이다. 후속 수정 및 최종 재검증은 [운영 준비 수정 결과](production-remediation.md)를 참조한다. 체크박스는 운영 환경에서 확인할 항목을 포함하며, 자동으로 완료 처리하지 않았다.

검토일: 2026-10-31. 코드 기준: `work`의 `20a720b`. 실제 스택은 **HTML/CSS·브라우저 ES Modules·로컬 Node 정적 서버·SheetJS·Google Maps/Places/Routes·Gemini/OpenAI/Claude**다. README의 공개 주소는 GitHub Pages다. React/Next.js/Tailwind/Vercel, 회원가입·결제·서버 세션은 현재 구현으로 확인되지 않았다.

**이 Node 개발 서버에 운영용 AI 키를 넣어 그대로 외부 공개하는 배포는 보류한다.** 환경 키 전달과 저장소 파일 노출을 먼저 제거해야 한다. GitHub Pages 정적 배포는 Node 서버와 실행 경로가 다르므로 동일한 취약점이 운영 사이트에서 재현됐다고 단정하지 않는다. 현재 배포 대상·도메인·릴리스 SHA를 확정한 뒤 해당 산출물을 점검한다.

체크박스는 앞으로 수행할 승인 기준이다. 체크하지 않은 항목은 미검증이다. 기존 실행 결과(단위 64개 통과, 모의 78개 중 70 통과·8 검증 불가, 실제 Gemini 일별 수정 성공)는 [직전 보고서](day-revision.md)에 있으며, 이번에 전체를 다시 실행한 것은 아니다. 새로운 발견은 기존 78개 검사 범위 밖에 있다.

현재 추적 파일 956개에서 설정된 실제 키와 제한된 비밀값 패턴은 발견하지 못했다. 추적 파일·조회 가능한 이력에서 `.env` 경로도 나오지 않았다. **전체 Git 이력의 전문 secret scanner 검사는 미실행**이다. `.gitignore`에는 `.env` 방지 규칙이 없다. [범위 및 결과](evidence/production-review/secret-scan.json).

좋은 기존 방어도 있다: HTML escape/safeUrl, 저장 실패 안내, 여행 저장의 탭 간 충돌 감지, AI 요청 timeout·취소, 일별 적용 전 비교, 다운로드 Object URL 회수가 구현돼 있다. Try-Catch나 리스너 정리가 전부 누락됐다고 일반화하지 않는다.

## 2. 기능 테스트: 주요 사용자 흐름

- [ ] 새 방문: 지도 키 없이 여행 생성 → 장소/메모 입력 → 저장 → 새로고침 → 같은 여행 재열기.
- [ ] 엑셀: XLSX/XLS/CSV, 한글 인코딩, 병합 날짜, 빈 행, 잘못된 파일, 확장자 위장, 크기 한도, 다중 시트 검증.
- [ ] 열 연결: 날짜·장소·시간·좌표 자동 추론을 확인하고 수동 변경 후 올바른 날짜/핀으로 표시.
- [ ] 장소 검색: 동명 지점·결과 0개·한글/영문/일문 이름·주소·사진 없음·폐업 후보 처리 확인.
- [ ] 일정 편집: 추가·삭제·날짜 이동·정렬·드래그·되돌리기·빠른 연속 클릭 후 데이터 보존.
- [ ] AI 하루 수정: 선택 날짜만 전송/수정, 잠금 유지, 추가/제외 항목 표시, 메모·다른 날짜 보존, 적용 전 원본 유지.
- [ ] AI 실패: 401/403/429/5xx/timeout/잘못된 JSON/불완전 출력/시간 충돌에서 부분 적용 없이 재시도 가능.
- [ ] 지도 경로: 교통수단·날짜·시간대·장소 순서·실제 응답과 직선 추정의 표시 구분.
- [ ] 상태 변화: 요청 중 여행/날짜 전환·취소·탭 닫기·뒤로 가기 → 오래된 응답이 현재 여행을 덮어쓰지 않음.
- [ ] 저장: 용량 부족·비공개 모드·손상 값·동시 탭 편집/삭제·페이지 종료 직전 입력 검사.
- [ ] 백업·복원: 원본 보존, 다른 브라우저 가져오기, 키·사진·리뷰 미포함, 미지원 버전·손상 JSON 거부.
- [ ] 내보내기: 엑셀·KML·오프라인 일정표·인쇄에서 날짜/한글/수식 주입 방어·외부 도구 호환 확인.
- [ ] 실제 API와 모의 API를 별도 실행·기록. 미실행 조건은 검증 불가로 표시.
- [ ] 회원가입/결제는 현재 해당 없음. 도입 시 이메일 검증, 재설정, 권한별 접근, 결제 중복 방지, 웹훅 서명·재전송·취소·환불까지 추가.

| 푸터 | 페이지 끝과 지도 하단까지 이동해 출처/약관/문의 링크 누르기 | 지도 저작권·출처가 가려지지 않고 링크 접근 가능 |
| 공개 운영 안내 | 키보드만으로 개인정보처리방침·약관·문의처 접근 | 앱에 현재 일반 푸터가 없으므로 설정/도움말 등 항상 접근 가능한 위치 마련 |
| 네트워크 복구 | 오프라인 전환 후 다시 온라인, 백그라운드 전환 후 복귀 | 저장 상태를 오인시키지 않고 중복 요청·영구 로딩 없음 |
| 접근성 | VoiceOver(iOS/macOS), TalkBack(Android), NVDA(Windows)로 주요 흐름 수행 | 레이블·상태 알림·초점·필수 입력 오류를 이해 가능 |

터치 목표는 가능하면 44×44 CSS px 이상, 일반 텍스트 대비 4.5:1 이상을 기준으로 삼는다. 크기 에뮬레이션·ARIA 속성 검사는 실기기 키보드나 스크린리더 발화 검사를 대체하지 않는다.

## 4. 성능·Lighthouse 최적화

- [ ] 배포된 HTTPS URL에서 첫 방문/재방문, 키 없음/지도 연결/대용량 여행을 나눠 측정. 동일 모바일 조건으로 3회 이상 실행해 변동도 기록.
- [ ] LCP ≤2.5초, INP ≤200ms, CLS ≤0.1을 필드 데이터 75백분위 목표로 사용. Lighthouse 실험실 TBT와 실제 INP는 별개로 판단.
- [ ] 초기 경로의 불필요한 JS/CSS를 줄이고 기능별 지연 로딩. 현재 XLSX 약 932KiB, app.js 약 208KiB, CSS 약 88KiB는 디스크 크기이며 전송 크기나 Lighthouse 점수가 아님.
- [ ] head의 동기 XLSX 스크립트를 필요 시 로드하고, 초기 의존성/업로드 버튼 준비 상태를 함께 처리. 무작정 async로 바꿔 전역 XLSX 참조를 깨뜨리지 않기.
- [ ] 큰 엑셀 파싱은 Worker·크기 제한·취소 기능. 긴 목록은 가상화/청크 렌더링, 계산 결과·패널별 변경을 분리.
- [ ] 지도·사진·상세 정보 캐시 크기와 동시 호출 상한, 여행 전환 후 정리를 확인.
- [ ] 소유한 이미지는 AVIF/WebP·srcset/sizes·적정 해상도·width/height 또는 aspect-ratio 적용. 첫 LCP 이미지는 lazy 제외, 화면 밖 이미지는 lazy.
- [ ] Google Places 사진은 제공 URL·크기 옵션·정책·출처를 따르며 임의 재호스팅/변환을 기본 해법으로 삼지 않기.
- [ ] 폰트는 WOFF2·필요 문자/굵기 최소화·fallback metrics 확인. 현재 Google Fonts의 display=swap은 이미 있음. 모든 폰트를 preload하지 말고 실제 필요한 1~2개만 검토.
- [ ] Brotli/gzip·HTTP/2 이상·CDN 적용. 해시 자산은 장기 immutable, HTML/공개 설정은 재검증, 비밀 응답은 no-store.
- [ ] 배포 직후 HTML과 JS 버전 불일치, 오래된 CDN 자산, 조건부 요청/304를 확인. 현재 로컬 서버에는 압축/ETag 생성이 없음.
- [ ] 20회 여행 전환·100회 상세 열기·모달 반복 후 힙 스냅샷, detached DOM, 이벤트 리스너·타이머·Object URL 조사. 추정만으로 메모리 누수라고 판정하지 않기.

Lighthouse는 이번에 실행하지 않았으며 점수는 제시하지 않는다. CI 목표값(예: 접근성/SEO 95 이상, 성능 90 이상)은 프로젝트의 네트워크·지도 SDK 비용을 고려해 정하고 점수만으로 출시를 판단하지 않는다.

## 5. SEO·분석 도구

- [ ] 공개 랜딩의 고유 title·description·lang=ko·실제 보이는 H1·논리적 제목 순서 확인. CSS로 숨긴 제목만 두지 않기.
- [ ] canonical을 최종 HTTPS 대표 URL로 지정. www/비www·슬래시·파라미터·GitHub Pages 하위 경로를 일관되게 처리.
- [ ] og:title/description/type/url/image 및 twitter:card 지정. 공유 이미지는 절대 URL·실제 200·올바른 MIME·권장 1200×630 크기.
- [ ] 검색 대상 랜딩과 개인 여행 작업 화면의 색인 정책을 분리. private/초대 링크는 접근 제어가 우선이며 noindex/robots는 인증 수단이 아님.
- [ ] 정적 HTML은 SSR로 전환하지 않아도 검색 가능. JS로만 생성되는 공개 핵심 콘텐츠는 렌더링된 HTML/URL 검사로 확인.
- [ ] sitemap에는 공개·정규 URL·200 응답만 포함. lastmod는 실제 변경일만 사용. sitemap XML의 이스케이프·네임스페이스·절대 URL 확인.
- [ ] robots.txt는 **호스트 루트**에서 제공. GitHub Pages 프로젝트의 `/HowdoIgetthere/robots.txt`는 `/robots.txt`를 대체하지 못한다. 호스트 루트 사이트 또는 커스텀 도메인에서 관리하고, 프로젝트 sitemap은 Search Console에 직접 제출 가능.
- [ ] 운영은 의도한 Allow 정책, 스테이징은 인증 및 적절한 noindex 정책. robots 차단으로 검색엔진이 noindex를 읽지 못하는 조합에 주의.
- [ ] Search Console 소유 확인·사이트맵 제출·대표 URL 색인 검사·404/리디렉션/공유 미리보기 검사.
- [ ] GA4를 도입한다면 동의 정책·운영/개발 속성 분리·단일 page_view 확인. 버튼 이벤트는 여행 생성/파일 가져오기/AI 요청·적용/내보내기 정도로 설계.
- [ ] DebugView·Realtime·Network에서 중복 이벤트와 실패 이벤트 확인. 여행명·위치·메모·API 키·원문 AI 요청을 GA4/에러 수집 서비스에 보내지 않기.
- [ ] 현재 GA4 설치는 확인되지 않았다. 분석 도구가 필요 없다면 미설치 자체는 결함이 아니며 운영 지표 수집 방법만 정한다.

설정 예시(파일·이미지를 실제로 만든 후 적용):

```html
<meta name="description" content="작성한 여행 일정을 지도에서 확인하고 날짜별로 편집하는 RouteFlow">
```

## 6. 보안·환경변수·DevSecOps

- [ ] `.env`, `.env.*`와 인증서/개인키/로그/백업을 ignore에 추가. 공유할 `.env.example`에는 값 대신 변수 설명만 넣는다.
- [ ] 현재 추적 파일뿐 아니라 모든 Git 이력·브랜치·태그, PR diff, 빌드 로그, 배포 산출물·소스맵을 secret scanner로 검사.
- [ ] 비밀값이 발견되면 먼저 폐기·재발급하고 접근/과금 로그 확인. git rm이나 이력 수정만으로 유출된 키가 안전해지지 않음.
- [ ] 개발/스테이징/운영 키와 프로젝트·쿼터를 분리하고 최소 권한·회전 담당자 지정.
- [ ] 브라우저 빌드에 포함되는 환경변수는 공개값으로 취급. NEXT_PUBLIC_·VITE_ 등 접두사도 비밀 보관 수단이 아님.
- [ ] 공용 AI 키는 서버 전용. 사용자 직접 입력 키를 유지할 때는 브라우저 저장의 XSS 위험·삭제 기능·전송 범위를 명확히 안내.
- [ ] Google Maps 브라우저 키는 공개 사용 전제로 운영 리퍼러·허용 API 제한, 별도 서버 키와 분리, 사용량 제한·알림 적용. 예산 알림은 강제 과금 상한이 아님.
- [ ] 운영 산출물에 localhost/127.0.0.1/내부 주소/테스트 키/디버그 플래그가 섞이지 않는지 검사. 문서·테스트 fixture의 예시 주소와 실행 코드의 API 주소를 구분.
- [ ] HTTPS 강제, 인증서 자동 갱신·혼합 콘텐츠 검사. HSTS는 HTTPS와 서브도메인 범위를 검증한 후 적용; preload를 무조건 켜지 않기.
- [ ] CSP는 Google 지도·사진·폰트·AI 연결 도메인을 실제 트래픽으로 정리해 Report-Only부터 검증. frame-ancestors, nosniff, Referrer-Policy, 필요한 Permissions-Policy 적용.
- [ ] 새 백엔드 CORS는 정확한 운영 Origin·메서드·헤더 허용 목록. credentials와 `*` Origin 조합 금지. CORS를 인증/권한 검증의 대체로 쓰지 않기.
- [ ] 현재 서버 세션은 해당 없음. 도입 시 세션 쿠키 `Secure; HttpOnly; SameSite=Lax`(서비스 흐름에 맞게), 최소 Path/Domain, 만료·로그아웃 폐기·로그인 시 ID 재발급 적용.
- [ ] 쿠키 인증으로 상태를 변경하는 요청은 CSRF 토큰·Origin 검증 정책을 적용한다. SameSite만으로 모든 CSRF 방어가 끝났다고 가정하지 않는다.
- [ ] 교차 사이트 쿠키가 필요한 경우 `SameSite=None; Secure`, CSRF 토큰·Origin 검증 추가. HttpOnly는 서버 Set-Cookie로 설정하며 localStorage에는 적용되지 않는다.
- [ ] vendored SheetJS/Anthropic SDK까지 버전·취약점·라이선스/SBOM 확인. 루트 의존성이 없다는 이유로 npm audit만 보고 안전하다고 결론내리지 않기.
- [ ] 로그·오류 추적에서 키/헤더/메모·요청 본문을 삭제하고 request ID·오류 코드·시간만으로 추적 가능하게 설계.
- [ ] 공개 약관·개인정보처리 안내·문의처, Google 데이터별 저장 정책·사진/리뷰 출처·삭제 정책 확인.
- [ ] PR 승인·필수 CI·제한된 배포 토큰·보호 환경·서명/출처 확인·변경 불가 아티팩트 사용. 운영 시크릿을 포크 PR에 전달하지 않기.
- [ ] 배포 SHA·설정 버전 기록 → 스테이징 동일 산출물 검사 → 배포 → HTTPS·필수 자산·API·저장 스모크 → 오류율/지연/API 비용 모니터링 → 실패 시 이전 산출물로 롤백.

파일/이력/빌드 검사 명령 예시(비밀값을 CI 로그에 출력하지 않도록 주의):

```bash
# 경로만 확인: .gitignore는 이미 추적 중인 파일을 제거하지 않는다.
git ls-files '.env*' '**/.env*'
git log --all --format= --name-only -- '.env' '.env.*' '**/.env' '**/.env.*'
git check-ignore -v .env .env.production

# 승인된 버전의 Gitleaks 설치 후 실행. 결과는 접근 제한된 아티팩트로 저장.
gitleaks git . --redact --report-format json --report-path /tmp/gitleaks-report.json

# 실제 배포 디렉터리에 맞게 dist를 바꾼다. 파일명만 출력.
rg -l --hidden 'localhost|127\.0\.0\.1|0\.0\.0\.0|http://' dist
```

현재 프로젝트에는 dist 빌드 단계가 없으므로 먼저 배포 자산 허용 목록/산출물 생성 단계를 정의해야 한다. 검사 중 잡힌 XML 네임스페이스 등의 `http://` 문자열은 혼합 콘텐츠 요청과 구분한다.

## 7. 출시 승인 기록

각 항목에 담당자·환경/브라우저 버전·재현 절차·기대값·실제값·증거·판정(통과/결함/검증 불가/해당 없음)·차단 여부를 기록한다. 이번 리뷰에서는 제품 코드를 수정하거나 배포하지 않았다. 실기기 4종, Safari/Firefox/Edge, Lighthouse, 운영 HTTPS/CORS/쿠키, GA4, 전체 Git 이력 secret scan, 대용량/힙 프로파일은 실행하지 않았다. 기존 8개 검증 불가에 대한 사용자 수용은 유지하되 상용 출시 담당자가 실제 지원 환경과 함께 수용 여부를 기록한다.
