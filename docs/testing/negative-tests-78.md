검증일: **2026-10-30 (Asia/Seoul)**. 대상: `wer134/HowdoIgetthere`, 원격 `main`과 일치하는 `de2ecb4808a2a422bbe90b59d43d398cc137abad`.

## 결과와 범위

항목 78개: **통과 45 · 결함 확인 25 · 검증 불가 8 · 항목 전체 해당 없음 0**. 계정 세션 만료와 미지원 핀 undo는 하위 케이스에서 해당 없음으로 구분한다. 한 항목의 일부만 통과하고 나머지가 미실행이면 전체 통과로 올리지 않았다. 결함이 하나라도 재현되면 해당 항목은 결함 확인이며, 나머지 하위 결과는 아래에 각각 남긴다.

**실제 Google API 호출 검증은 0건이다.** 환경의 비밀값/변수 구성에 Google 키가 없었으며, 이 테스트 브라우저의 외부 네트워크 요청을 차단했다. Google의 검색/사진/상세/경로는 가짜 SDK 응답이고 MapView는 호출 기록 대역이다. 실제 앱의 `app.js`, 검색/캐시/재시도/정규화/경로/파일 모듈은 그대로 실행했다. 모의 통과는 Google 권한·쿼터·결제·실제 지도 표시·장소 품질의 통과를 의미하지 않는다. PNG의 "지도 연결됨"도 대역 상태이며, 빈 지도 배경은 대역의 한계이지 지도 렌더링 결함의 증거가 아니다.

브라우저: 별도 Chromium 154.0.8037.57 프로세스, 항목별 격리 BrowserContext(비영속 임시 프로필), Playwright 1.62.1, Node 24.19.0. 실제 사용자 브라우저/여행/키를 사용하지 않았다. 다중 탭 검사는 그 항목의 컨텍스트 안에서만 저장소를 공유했다. 기본 화면은 1440×900, 모바일 대체 검사는 390px. 로그 시각은 UTC이고 화면의 날짜는 서울 시간대다(15번은 시간대 변경).

앱 소스·기존 테스트·의존성 선언·잠금 파일은 변경하지 않았다. 이번에 추가한 파일은 이 보고서, 재현 도구, 증거뿐이다. 기존 `npm test`도 **26/26 통과**했으며 [원문 출력](evidence/negative-78/unit-tests.txt)을 보존했다. 기존 테스트의 성공은 이번 결함을 부정하지 않는다.

## 재현과 증거 읽는 방법

[사용자가 제공한 원문](repro/negative-tests-78-input.txt), [전체 재현 스크립트](repro/negative-78.cjs), [SDK 대역](repro/google-mock.js), [지도 호출 대역](repro/mapview-mock.js), [집계 JSON](evidence/negative-78/results.json)을 함께 제공한다.

저장소 루트에서 별도 터미널로 실행한다. 설치된 Playwright가 제공되는 환경의 `NODE_PATH`를 유지한다. 서버는 루프백에서만 실행한다.

```bash
cd /workspace/HowdoIgetthere
PORT=8093 node server.js --no-open
```

다른 터미널에서:

```bash
cd /workspace/HowdoIgetthere
APP_URL=http://127.0.0.1:8093 node docs/testing/repro/negative-78.cjs
# 특정 항목만 재현
ONLY=8,9,60 APP_URL=http://127.0.0.1:8093 node docs/testing/repro/negative-78.cjs
python docs/testing/repro/render-report.py
```

재현 스크립트는 결함이 있으면 종료 코드 1, 도구 실행 오류가 남으면 2를 반환한다. 외부 선행 조건 때문에 검증 불가인 항목은 결과에 명시한다. ONLY 실행은 선택 항목 증거만 덮어쓰고 나머지 기존 증거를 유지하므로, 새 전체 검증은 ONLY 없이 실행해야 한다. 모든 JSON에 시작·종료 시각이 있다. 결과 생성기는 각 항목 증거를 읽으며 테스트를 대신 실행하지 않는다.

공통 사전 조건: 테스트 저장소에 A(첫 장소·둘째 장소는 11/1, 셋째 장소는 11/2; 일정 날짜 배열은 11/1~3)와 B(다른 여행 장소 1개)를 넣고 UI의 저장 여행 목록으로 연다. Place ID/좌표는 전용 fixture다. 별도 표기 없는 항목은 이 사전 조건과 모의 SDK를 사용한다. 특수 전제(스토리지 실패·손상 타입·지도 지연 등)는 재현 절차/실제 결과에 구체적으로 기록한다.

각 PNG는 해당 항목의 최종 화면이다. 새로고침 전 초안·중간 상태 등은 최종 PNG만으로 입증하지 않으며 JSON의 실행 관측값을 함께 본다. 소스 검토 근거는 동적 실행의 대체가 아니다. JSON의 console error에는 의도적으로 차단한 외부 폰트와 모의 사진 404도 포함되므로 앱 오류와 구분한다.
