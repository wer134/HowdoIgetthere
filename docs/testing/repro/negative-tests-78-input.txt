RouteFlow의 부정 테스트 목록 78개입니다. 현재 체크아웃 de2ecb4를 기준으로 아래 항목을 모두 검증해 주세요.

검증 규칙:
- 별도 브라우저 프로필과 테스트용 여행·파일을 사용합니다.
- 실제 Google API 키가 없어도 가능한 UI·저장·편집 테스트와 모의 API 테스트부터 진행합니다.
- 통과 / 결함 확인 / 검증 불가 / 해당 없음을 구분합니다. 로그인 기능처럼 현재 없는 기능은 해당 없음으로 기록합니다.
- 모의 응답 검증을 실제 Google 연동 검증으로 표시하지 않습니다.
- 항목별 사전 조건, 재현 절차, 기대 결과, 실제 결과, 증거, 심각도를 기록합니다.
- 한 항목 안에 여러 조건이 있으면 하위 케이스로 나누고, 일부만 실행했으면 전체 통과로 처리하지 않습니다.
- 소스 검토와 실제 브라우저 실행 결과를 구분합니다.
- 결과를 docs/testing/negative-tests-78.md에 작성하고 재현 스크립트·증거 경로를 연결합니다.
- 우선 검증과 결함 보고를 수행합니다. 테스트를 통과시키기 위해 기존 기능이나 테스트 조건을 임의로 제거하지 않습니다.
- 응답과 결과 보고서는 한국어로 작성합니다.
기본 비정상 인터랙션
1. 검색 중 네트워크 끊김: 요청 도중 오프라인으로 전환하고 복구한다. 로딩·버튼이 복원되고 입력과 기존 결과가 유지되는지 확인한다.
2. 중복 제출: 여행 생성·일정 추가·적용 버튼을 연속 클릭하고 Enter와 클릭을 동시에 실행한다. 중복 데이터와 중복 요청이 생기지 않아야 한다.
3. 편집 중 이탈: 저장 전 입력, 드래그 직후 뒤로 가기·새로고침·탭 종료를 실행한다. 미저장 상태가 안내되거나 복원되어야 한다.
4. API 권한 없음: 잘못된 키, 리퍼러 제한, Places API 비활성화 응답을 재현한다. 결과 없음과 권한 오류를 구분하고 로컬 편집은 가능해야 한다.
5. 인증 상태 상실: 사용 중 API 키를 제거·무효화한다. 입력을 잃지 않고 오류에서 복구되어야 한다. 계정 세션 만료는 로그인 기능 존재 여부를 먼저 확인한다.
6. 검색 응답 역전: A 요청을 지연시키고 B 검색 또는 다른 여행 열기를 실행한다. A 응답이 현재 결과나 다른 여행을 덮어쓰지 않아야 한다.
7. 저장 공간 부족: 저장소 용량 초과·쓰기 실패를 재현한다. 거짓 저장 완료가 표시되지 않고 이전 정상 저장본을 유지해야 한다.
8. 다중 탭 충돌: 두 탭에서 같은 여행을 각각 삭제·수정하고 저장한다. 조용한 덮어쓰기와 삭제 항목 부활 여부를 확인한다.
9. 이동·삭제·되돌리기 혼합: 이동 직후 삭제·되돌리기를 실행하고 날짜 필터·여행도 전환한다. 대상 여행·장소·핀·순서가 일치해야 한다.
10. 악성·손상 입력: HTML·스크립트 문자열, 매우 긴 메모, 잘못된 좌표, 손상 파일·저장 데이터를 넣는다. 스크립트 실행·멈춤·정상 데이터 손실이 없어야 한다.
여행 생성·날짜·시간
11. 여행 이름에 공백·줄바꿈만 입력한다. 의미 없는 제목의 여행이 생성되지 않아야 한다.
12. 같은 이름의 여행을 여러 개 만든다. 날짜·수정 시각 등으로 구분되고 서로 독립적으로 관리되어야 한다.
13. 여행 일수를 0·음수·소수·매우 큰 값으로 조작한다. 처리 단계에서도 범위를 검증해야 한다.
14. 출발일을 연말·월말·윤년 2월 말로 설정한다. 날짜 중복·누락이 없어야 한다.
15. 여행 생성 후 기기 시간대를 바꾼다. 여행 날짜가 하루 앞뒤로 바뀌지 않아야 한다.
16. 여행 기간 밖의 날짜에 장소를 배치한다. 추가 장소가 숨지 않고 기간 확장 또는 해당 날짜가 명확히 표시되어야 한다.
17. 11/1, 11월 1일, 2026-11-01을 섞어 입력한다. 같은 날짜가 어떻게 처리되는지 확인하고 모호한 해석을 경고해야 한다.
18. 종료 시간이 시작 시간보다 빠르게 입력한다. 자정 넘김과 입력 오류가 구분되고 음수 시간이 정상처럼 표시되지 않아야 한다.
19. 24:00, 25:30, 오전 12시, 시간 미정을 입력한다. 지원하지 않는 형식을 조용히 잘못 해석하지 않아야 한다.
20. 날짜의 마지막 장소를 다른 날로 옮긴다. 빈 날짜에도 다시 장소를 넣을 수 있어야 한다.
장소 검색·보관함
21. 도시 없이 흔한 상호명을 검색한다. 결과의 국가·도시·주소를 식별하고 동명 장소를 구분할 수 있어야 한다.
22. 검색 직전·직후 입력값을 바꾼다. 결과가 어느 검색어에 대한 것인지 명확해야 한다.
23. 결과 0건이 나온 뒤 이전 결과의 선택 버튼을 조작한다. 이전 장소가 새 결과처럼 추가되지 않아야 한다.
24. 결과 수가 많고 이름·주소가 매우 긴 데이터를 표시한다. 버튼과 내용이 잘리거나 겹치지 않아야 한다.
25. 동일 Place ID의 장소를 한국어·영어·일본어 이름으로 보관한다. 이름 차이만으로 불필요한 중복이 생기지 않아야 한다.
26. 이름은 같지만 Place ID·주소가 다른 지점을 보관한다. 서로 다른 지점이 합쳐지지 않아야 한다.
27. 개인 메모가 있는 장소를 검색 결과에서 다시 보관한다. 기존 메모가 빈 값으로 덮어써지지 않아야 한다.
28. 사진 없음과 사진 요청 실패를 각각 재현한다. 서로 다른 상태를 구분해 안내해야 한다.
29. 대표 사진과 모든 대체 사진을 실패시킨다. 무한 재시도와 요청 폭증이 없어야 한다.
30. 보관 후 폐업·이전·이름 변경된 장소를 일정에 넣는 상황을 재현한다. 오래된 정보를 최신 정보처럼 확정하지 않아야 한다.
31. 보관함 메모를 입력하자마자 탭 전환·새로고침한다. 저장 시점과 입력 손실 여부를 확인한다.
32. 여러 날짜에 배치된 장소를 보관함에서 삭제한다. 보관함 삭제와 일정 삭제의 범위가 분명하고 의도대로 동작해야 한다.
일정 편집·드래그·되돌리기
33. 수정 패널에서 저장하지 않은 상태로 다른 일정의 수정 버튼을 누른다. 입력을 조용히 잃지 않아야 한다.
34. 교체 후보를 선택한 뒤 장소명을 직접 바꾼다. 이름과 다른 장소의 좌표가 잘못 결합되지 않아야 한다.
35. 시간·메모만 수정한다. 불필요한 장소 재검색이나 좌표 변경이 없어야 한다.
36. 시간을 유지한 채 다른 날짜로 이동한다. 새 날짜의 일정 충돌이 어떻게 표시되는지 확인한다.
37. 같은 장소를 하루 두 번 또는 여러 날 배치한 뒤 하나만 수정한다. 다른 방문 일정까지 변경되지 않아야 한다.
38. 필터가 적용된 목록에서 순서를 바꾼다. 숨겨진 항목을 포함한 실제 배치 위치가 예측 가능해야 한다.
39. 선택한 장소를 삭제한 뒤 수정·이동을 시도한다. 옆 항목이 대신 수정되거나 상세 패널이 남지 않아야 한다.
40. 드래그 중 Escape 또는 창 밖 드롭으로 취소한다. 원래 데이터와 화면 상태가 유지되어야 한다.
41. 장소를 자기 자신 위에 드롭한다. 불필요한 변경·저장·API 요청이 없어야 한다.
42. 드래그 중 날짜 필터나 목록을 바꾼다. 다른 항목이 이동하지 않고 대상 유효성이 검증되어야 한다.
43. 삭제 후 새 장소를 추가한 다음 이전 삭제를 되돌린다. 후속 작업을 조용히 잃거나 잘못된 과거 상태로 돌아가지 않아야 한다.
44. 되돌리기를 연속 클릭한다. 같은 항목이 여러 번 복원되지 않아야 한다.
45. 되돌리기 알림이 있는 동안 다른 알림을 발생시킨다. 취소 기회가 사라지는지와 대체 접근 방법을 확인한다.
46. 삭제 확인창에서 취소·닫기를 실행한다. 삭제·저장 후처리가 실행되지 않아야 한다.
지도·경로·외부 API
47. 지도 초기화를 지연시킨 상태에서 저장한 여행을 연다. 지도 준비 후 현재 여행의 핀이 표시되어야 한다.
48. 지도 초기화 중 다른 여행으로 전환한다. 이전 여행의 핀이 뒤늦게 나타나지 않아야 한다.
49. 날짜 필터를 빠르게 반복 변경한다. 날짜별 핀과 보관함 핀의 표시 규칙이 유지되어야 한다.
50. 지도 핀 이동 후 취소·되돌리기를 실행한다. 지원 여부를 확인하고, 지원한다면 좌표·주소·경로도 일관되게 복원되어야 한다.
51. 경로 계산 중 장소를 이동·삭제한다. 오래된 경로 응답이 현재 일정에 반영되지 않아야 한다.
52. 동일 좌표 또는 매우 가까운 장소를 연속 배치한다. 0거리 처리 오류와 불필요한 경로 요청이 없어야 한다.
53. 섬·국경·장거리 구간을 도보·대중교통으로 요청한다. 경로 없음을 0분으로 표시하지 않아야 한다.
54. 일부 구간만 경로 조회에 성공시킨다. 전체 완료로 오인하게 하지 않고 미확인 구간을 표시해야 한다.
55. 쿼터 초과·결제 중단 응답을 재현한다. 재시도가 제한되고 원인에 맞는 안내가 제공되어야 한다.
56. 장소 선택·날짜 탭 전환을 빠르게 반복한다. 동일 사진·상세 정보의 불필요한 중복 요청 수를 측정한다.
저장·복원·가져오기·내보내기
57. 현재 열려 있는 여행의 저장본을 삭제한다. 자동 저장으로 삭제한 여행이 의도 없이 부활하지 않아야 한다.
58. 일부만 유효한 여행 데이터를 복원한다. 기존 정상 여행을 먼저 파괴하지 않고 오류·부분 복구 상태를 안내해야 한다.
59. 이전 저장 형식의 여행을 새 버전에서 연다. 호환 처리 또는 명확한 안내가 있고 원본이 보존되어야 한다.
60. 저장 데이터의 여행 ID·수정 시각·배열·필드 타입을 변조한다. 다른 여행 덮어쓰기와 화면 멈춤이 없어야 한다.
61. 확장자만 .xlsx인 다른 형식 파일을 가져온다. 실패해도 현재 여행이 유지되어야 한다.
62. 빈 파일·빈 시트·헤더만 있는 파일을 가져온다. 결과가 명확히 안내되고 다른 파일이나 시트를 선택할 수 있어야 한다.
63. 병합 날짜·숨겨진 행·여러 시트가 있는 파일을 가져온다. 날짜 상속·제외 행·선택 시트의 처리 결과를 확인한다.
64. 장소·날짜 열을 동일하거나 잘못된 열로 연결한다. 잘못된 해석을 사용자가 발견하고 수정할 수 있어야 한다.
65. 내보낸 파일을 다시 가져온다. 장소·시간·메모·방문 순서·좌표의 왕복 보존 여부를 비교한다.
66. =, +, @, - 등으로 시작하는 외부 문자열을 엑셀·CSV로 내보낸다. 의도하지 않은 수식으로 변환되는지 파일 구조를 검증한다. 위험한 수식을 실제 실행하지 않는다.
67. 특수문자·HTML·위험한 URL을 포함한 장소를 KML로 내보낸다. XML이 유효하고 위험한 링크가 안전하게 처리되어야 한다.
68. 모바일에서 다운로드를 취소하거나 차단한다. 앱이 실제 파일 저장 완료를 보장하는 것처럼 잘못 안내하지 않아야 한다.
모바일·접근성·개인정보
69. 모바일 키보드를 연 상태로 장소·메모를 수정한다. 입력·오류·저장 버튼에 접근할 수 있어야 한다. 실기기가 없으면 검증 범위를 명시한다.
70. 입력 중 화면 회전·창 크기 변경을 실행한다. 입력이 유지되고 패널이 화면 밖에 남지 않아야 한다.
71. 지도 위에서 페이지 스크롤을 시도한다. 지도 제스처에 갇히지 않고 패널과 페이지를 조작할 수 있어야 한다.
72. 텍스트를 200% 확대하고 긴 한국어 이름을 표시한다. 내용과 버튼이 잘리거나 겹치지 않아야 한다.
73. 키보드만으로 장소 배치·날짜 이동·순서 변경을 수행한다. 드래그 없이 동일 기능을 사용할 수 있어야 한다.
74. 모달에서 Tab·Shift+Tab·Escape를 반복한다. 포커스 범위와 닫은 뒤 복귀 위치가 적절해야 한다.
75. 스크린리더로 검색 결과·저장 실패·되돌리기를 확인한다. 접근성 트리 검사와 실제 스크린리더 검증을 구분한다.
76. 공용 기기 상황에서 여행·키를 저장한 뒤 다음 사용자가 접속한다. 저장 사실 안내와 키·여행·캐시 삭제 경로를 확인한다.
77. 외부 링크에 javascript:, data: 및 조작된 주소를 넣는다. 허용되지 않은 프로토콜로 코드가 실행되지 않아야 한다.
78. 패널을 반복해서 열고 닫은 뒤 뒤쪽 지도·버튼을 조작한다. 보이지 않는 요소가 클릭이나 포커스를 가로채지 않아야 한다.
우선 실행 순서는 데이터 손실·오염 → 잘못된 여행에 반영 → 중복 요청·과금 → 나머지 UI·접근성으로 잡되, 최종 보고서에는 1~78번 전체의 결과를 빠짐없이 기록해 주세요.
